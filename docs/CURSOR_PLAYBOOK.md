# Cursor playbook — новый бренд в reglament-to

Цель: по фото СТС + пробегу (+ чекам, если есть) собрать публичную страницу регламента ТО **так же**, как `brands/exeed-rx/`, без полного OCR-пайплайна в коде.

Работай в корне репо `reglament-to`. Эталон стиля и секций: `brands/exeed-rx/`.

---

## 0. Входы от пользователя

Собери (минимум жирным):

| Вход | Зачем |
|---|---|
| **Фото СТС** (лицевая + оборот) | Марка, модель, год, VIN, мощность, масса, госномер, цвет |
| **Текущий пробег** (км) | Какой пакет ТО актуален |
| Чеки / заказ-наряды | Секция «Отчёт», факты цен |
| Предпочтения СТО / город | Ориентиры по ценам |
| Пороги (выезжают / нет) | Блок подъёмника |
| Контакт для «заказать такое же» | Ссылка Max / мессенджер в README |

Положи сырьё в `brands/<slug>/docs/sts/`, `docs/receipts/` (не коммить `.wav` и лишние секреты).

---

## 1. Создать каркас бренда

```text
brands/<slug>/
  index.html
  assets/css/style.css
  assets/js/main.js
  assets/img/
  docs/
  .ai/CONTEXT.md
  .ai/INDEX.md
  .ai/state.json
```

1. Скопируй `brands/exeed-rx/` → `brands/<slug>/`  
2. Удали чужие чеки/hero, оставь структуру HTML/CSS/JS  
3. Обнови `.ai`: факты авто, пути без префикса `EXEED/`  

Slug: lowercase + дефис (`exeed-rx`). См. [BRAND_TEMPLATE.md](BRAND_TEMPLATE.md).

---

## 2. Разобрать СТС (вручную / с агентом по фото)

Из фото (инструмент Read умеет картинки) выпиши в `.ai/CONTEXT.md` и в `#specs`:

- Марка / модель / год / госномер  
- VIN (проверь год по 10-й позиции, если применимо)  
- Двигатель, кВт / л.с., категория, цвет, массы  
- КПП — только если уверенно известно; иначе оговорка  

Не выдумывай цифры. Сомнительное — в blockers `state.json`.

---

## 3. Исследовать регламент ТО

Источники (приоритет доступности из РФ):

1. Официальный сайт дистрибьютора / сервисная книжка PDF  
2. Дилерские прайсы ТО по пробегу  
3. Форумы / Telegram-каналы владельцев — только как вторичка, с пометкой  

Собери:

- Интервал ТО (обычно 10 тыс. км / 12 мес — уточни для модели)  
- Состав пакетов ТО-0…ТО-N (масло, фильтры, свечи, АКПП/DCT, тормоза…)  
- Типичные артикулы расходников (OEM + аналоги)  
- Ориентир цен работ/материалов в городе пользователя  

Черновик регламента — `brands/<slug>/docs/TO-<пакет>_<пробег>.md`.

---

## 4. Подъёмник и пороги

Короткий файл `docs/porogi_lift.md`:

- Выезжают ли пороги / нужна ли рамка  
- Рекомендация: двухстоечный / ножничный / яма  
- Aftermarket-оговорки  

Секция `#lift` на сайте — без воды, 1–2 практических абзаца + таблица если нужно.

---

## 5. Собрать `index.html`

Стиль: educational-sites (ОУД4) — см. workspace rule `educational-sites-style`.

Порядок работы:

1. Hero: бренд крупно, один H1, пробег/пакет, 1–2 CTA  
2. Заполнить specs из СТС  
3. Timeline графика ТО (`data-step`)  
4. Состав пакетов (tabs `data-tab` / `data-panel`)  
5. Расходники — таблица артикулов  
6. Подъёмник  
7. Отчёт: если есть чеки — суммы + галерея; иначе «пока нет факта»  

Копируй `main.js` и базовый CSS с `exeed-rx`; правь только контент и hero-image.

Hero-фото: реальное авто или нейтральный stock в `assets/img/`. Чеки для отчёта — в `assets/img/` (сжатые JPEG).

---

## 6. Секция отчёта (если были работы)

1. Разложи чеки в `docs/receipts/` и копии в `assets/img/`  
2. Сведи суммы в таблице (материалы / работы / доставка)  
3. Текст для Max — `docs/message_max.md` (коротко, с ссылкой на `#report`)  
4. Не округляй «на глаз», если на чеке видна точная сумма

## 7. Деплой

### GitHub Pages (основной демо)

```bash
# из корня reglament-to
git add brands/<slug> docs README.md index.html marketing
git commit -m "Add brand <slug> TO reglament site"
git push origin main
```

Pages: Settings → Pages → branch `main` / root.

Корневой `index.html` редиректит на первый демо-бренд; при каталоге — добавь список ссылок.
